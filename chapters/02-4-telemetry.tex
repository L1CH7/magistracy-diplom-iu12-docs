\section{Подсистема телеметрии и интеграция с внешними клиентами}

Своевременное предоставление аналитических данных о состоянии транспортной сети является важнейшим требованием для систем поддержки принятия решений. Для минимизации задержек при трансляции состояния сети разработана высокопроизводительная подсистема телеметрии.

Асинхронная архитектура трансляции состояния сети.
Для обеспечения непрерывной передачи данных без блокировок симулятора, подсистема телеметрии функционирует в выделенном фоновом потоке, который общается с вычислительным ядром через безблокировочную очередь сообщений \cite{lock_free_queue}. 

На каждом шаге симуляции модуль симуляции формирует компактные дельты изменений (идентификатор ребра, текущее количество транспортных средств, вычисленная скорость и текущий индекс задержки TTI). Дельты сериализуются в бинарный поток фиксированного формата и отправляются в очередь телеметрии. Фоновый поток забирает сообщения из очереди, преобразует их в бинарные фреймы и отправляет на сетевой шлюз через сокет сетевого транспорта. Сетевой шлюз, в свою очередь, осуществляет трансляцию данных подключенным веб-клиентам по протоколу WebSocket.

Данная архитектура обеспечивает полную изоляцию сетевых операций от вычислительного ядра: задержки в сетевом транспорте или медленный рендеринг на стороне клиента никак не влияют на скорость работы симулятора и роутера.

Формирование тепловой карты загруженности и агрегация метрик.
Для интеграции с внешними геоинформационными системами и веб-картами в реальном времени формируется тепловая карта загруженности дорожной сети. 

Агрегация метрик выполняется на стороне шлюза. Полученные от симулятора дельты изменений группируются по 5-минутным временным интервалам для сглаживания мгновенных флуктуаций. Для каждого ребра графа вычисляется отношение текущей скорости к максимально разрешенной:
\begin{equation}
    K_{congestion} = \frac{V_{current}}{V_{max}}
\end{equation}

Значение $K_{congestion}$ отображается на цветовую шкалу градиента от зеленого (свободное движение, $K_{congestion} \approx 1.0$) через желтый к красному (полный затор, $K_{congestion} \approx 0.0$). 

Данные тепловой карты кэшируются на сетевом шлюзе и отдаются клиентам по протоколу WebSocket в формате бинарных векторных тайлов, оптимизированных для аппаратного рендеринга на графическом процессоре веб-браузера. Это позволяет отображать динамику заторов на карте города с частотой обновления до 60 кадров в секунду даже при сотнях тысяч одновременно симулируемых агентов.
