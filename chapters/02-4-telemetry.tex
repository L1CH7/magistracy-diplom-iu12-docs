\section{Подсистема сбора метрик и интеграция с внешними системами}

Своевременный сбор и экспорт аналитических данных о состоянии транспортной сети и показателях производительности вычислительного ядра необходимы для мониторинга и последующего анализа эффективности алгоритмов маршрутизации. Для решения этих задач разработана подсистема экспорта телеметрии и метрик.

Для предотвращения блокировок основного симуляционного цикла операции вывода данных изолированы в фоновом сетевом потоке. Взаимодействие между симулятором и фоновым потоком построено по схеме двойной буферизации без использования примитивов синхронизации. Движок записывает состояния агентов в свободный буфер, после чего атомарно меняет индекс активного буфера местами.

На каждом шаге симуляции ядро формирует бинарные пакеты телеметрии фиксированного формата \texttt{AgentState}, включающие:
\begin{itemize}
    \item уникальный идентификатор агента (\texttt{agent\_id});
    \item идентификатор текущего ребра дорожного графа (\texttt{current\_edge});
    \item текущее положение агента на сегменте в метрах (\texttt{pos\_meters}).
\end{itemize}

С частотой до 25 Гц фоновый поток считывает накопленные фреймы и транслирует их по протоколу ZeroMQ через PUB-сокет во внешние системы. Сетевой шлюз десериализует бинарный поток и ретранслирует сырые метрики по протоколу WebSocket аналитическим сервисам.

Помимо трансляции состояния агентов в реальном времени, в ядре реализован механизм опроса внутренних метрик производительности системы. Сбор метрик осуществляется по запросу через выделенный сетевой эндпоинт шлюза \texttt{/api/v1/sim/stats}. При поступлении запроса шлюз запрашивает диагностические параметры у ядра по бинарному протоколу ZeroMQ REQ (команда \texttt{STATS}, код 9).

Ядро формирует текстовый JSON-пакет, включающий следующие группы накопленных параметров производительности и состояния симуляции:
\begin{itemize}
    \item показатели заторов: глобальный индекс задержки TTI (Travel Time Index) и общее число отобранных временных замеров;
    \item состояние симулируемых агентов: количество активных, находящихся в пути (\texttt{driving}), ожидающих появления (\texttt{waiting\_spawn}), завершивших поездку (\texttt{completed}) и простаивающих агентов;
    \item метрики надежности и интенсивности маршрутизации: суммарное число построенных, успешных, отброшенных как устаревшие (\texttt{stale}) и аварийно завершившихся (\texttt{failed}) маршрутов, а также количество перевыборов пути (\texttt{reroutes});
    \item временные показатели поисковых потоков: среднее и максимальное время поиска пути в микросекундах, а также время ожидания потока в очереди задач роутера (\texttt{router\_wait\_time\_us});
    \item вычислительная сложность: среднее число итераций и посещенных вершин графа при поиске пути;
    \item диагностика утилизации системы: коэффициент загрузки пула потоков маршрутизатора (\texttt{router\_load});
    \item параметры конфигурации симуляции: текущее ускорение времени (\texttt{acceleration}), коэффициент масштабирования агентов (\texttt{asf}), количество и размерность 5-минутных временных бакетов для динамических профилей.
\end{itemize}

Полученный JSON-пакет возвращается через шлюз во внешние аналитические системы. Такой подход позволяет внешним инструментам производить опрос метрик с необходимой периодичностью и агрегировать собранные данные в структурированные форматы, например, CSV, для последующего анализа масштабируемости и верификации алгоритмов динамической маршрутизации.
