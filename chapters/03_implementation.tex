\section{High-Performance Implementation Details}
\label{sec:implementation}

We construct our single-threaded routing engine in C++ using data-oriented design principles to maximize hardware efficiency \cite{drepper2007memory}. 
We pack the road network topology into a Compressed Sparse Row (CSR) layout. 
To incorporate traffic turn restrictions without conditional jumps in the hot loop, we apply dual graph line inversion. 
Road segments become nodes in our computational graph, and turns at intersections become edges. 
This Edge-Based Graph representation maps turn penalties to static edge weights.

We apply a topological node reordering scheme based on the Morton spatial curve (Z-curve) during graph compilation. 
The reordering assigns adjacent memory addresses to spatial neighbors on the map. 
This spatial locality allows the hardware prefetcher to load neighboring nodes into the L1/L2 caches before search access. 

We represent the dynamic traffic states using an Array of Structures (AoS) format. 
We align each segment state structure to 64-byte boundaries using the \verb|alignas(64)| directive. 
This alignment prevents cache line splitting and guarantees that a single cache transaction retrieves the node state. 
To eliminate runtime weight calculation overhead, we pre-bake link delay metrics directly into flat binary graph dumps. The routing loop reads precomputed integer edge weights from memory as static values, avoiding floating-point division and BPR function evaluation in the hot path.

We implement a cache-conscious SIMD 8-ary priority heap to reduce tree traversal depth. 
The 8-ary structure matches the width of the AVX2 vector register: eight 32-bit child keys occupy exactly 256 bits, saturating one SIMD load instruction with no wasted lanes. 
We vectorize the child node search step using AVX2 intrinsics, aligning with hardware-level optimization guidelines for SIMD registers, data packing, and alignment on x86 architectures \cite{kusswurm2014modern}. 
The child search routine uses the \verb|_mm256_min_epu32| instruction to locate the minimum among all eight child keys within a single 256-bit register, representing an instruction-level parallel operation executing on one CPU core. 
This instruction eliminates scalar branch instructions during the down-heap traversal and reduces the hot-loop critical path. This design explicitly targets modern x86-64 desktop and server architectures supporting AVX2 instructions, trading platform portability (e.g., to ARM or Apple Silicon architectures) for maximum low-level vectorization throughput.
 

We apply joint word encoding to represent heap elements. 
We pack the 29-bit distance key and the 3-bit local child index into a single 32-bit word. 
The horizontal SIMD minimum then returns the packed winner, so the minimum child key and its position decode in two bitwise operations with zero additional comparisons. 
This format also avoids pointer indirection. 

We precompute the ALT landmark distance table with exactly sixteen landmarks. 
Each landmark stores one 32-bit distance value; sixteen entries occupy $16 \times 4 = 64$ bytes, which fits exactly one CPU cache line. 
The ALT heuristic evaluation loop loads all sixteen landmark bounds in a single cache transaction and processes them without L1 misses. 

We utilize Target Register Caching to optimize coordinate access during A* and ALT searches. 
We load destination coordinates and landmark bounds into CPU registers before entering the main loop. 
This step reduces register pressure and eliminates stack spill operations. 

Metropolitan graphs containing 1.2 million nodes require rapid state cleanup between queries. 
Re-initializing the distance tracking array requires $O(V)$ operations, which dominates execution time for localized queries. 
We implement an $O(\text{active})$ partial fast-clearing mechanism. 
We maintain a thread-local stack of visited node indices during traversal. 
After a query terminates, we iterate over the active stack to reset the modified distance values to infinity. 
This approach restricts cleanup costs to the size of the relaxed search space.

\subsection{System-Level and Data-Oriented Optimizations Checklist}
Apart from priority queue structures, we apply a set of hardware-level optimizations to accelerate the routing engine across all evaluated configurations. We summarize these core optimization techniques below:
\begin{itemize}
    \item \textbf{Data-Oriented Memory Layout}: We store the graph topology in the Compressed Sparse Row (CSR) format to minimize memory indirection \cite{drepper2007memory}.
    \item \textbf{Topological Cache-Conscious Reordering}: We reorder node indices along the Morton spatial curve (Z-curve) to match physical coordinate proximity, allowing the hardware prefetcher to load adjacent nodes into L1/L2 caches \cite{drepper2007memory, morton1966computer}.
    \item \textbf{AoS Structure Alignment}: We encapsulate dynamic traffic state updates in an Array of Structures (AoS) where each record is padded to 64 bytes using the \verb|alignas(64)| directive. This alignment guarantees that a single transaction loads the segment state and prevents cache line split penalties \cite{drepper2007memory}.
    \item \textbf{Pre-Baked Edge Weights}: We eliminate runtime traffic delay computations in the hot loop by pre-baking all link travel times into static integer arrays during graph compilation, bypassing dynamic BPR function evaluation \cite{drepper2007memory, fog_optimizing_cpp}.
    \item \textbf{Temporal FIFO Linear Interpolation}: To prevent FIFO property violations caused by 5-minute time discretisation, we apply linear interpolation to penalties across adjacent intervals, ensuring time-consistency of routing costs \cite{goldberg2005external}.
    \item \textbf{Memory-Mapped Flat Serialization}: We bypass runtime geometry parsing and graph serialization overheads by mapping compiled binary files directly into virtual memory via the \verb|mmap| system call \cite{drepper2007memory}.
    \item \textbf{Thread-to-Core Binding (CPU Affinity)}: To stabilize execution latency measurements, we pin the benchmarking thread to a dedicated physical CPU core, preventing OS scheduler migration and L1/L2 cache invalidations \cite{ribeiro2008memory}.

    \item \textbf{Fast Partial-State Reinitialization}: We clear search state markers in $O(\text{active})$ time using a visited stack, bypassing $O(V)$ re-initialization sweeps on localized queries.
\end{itemize}

\subsection{Precomputation and Landmarked Pre-Baked Data}
To support fast ALT queries, we perform offline precomputation of landmark distances. Our preprocessing pipeline implements a three-level data flow. First, raw geometries are imported into a PostgreSQL database and transformed into an Edge-Based Graph representation to represent turn penalties statically. Second, the landmark selection routine generates 128 candidate landmarks using MinMax (Farthest) and Avoid heuristics. We then select exactly sixteen landmarks from this candidate set using the MaxCover stochastic optimization algorithm \cite{fuchs2010preprocessing}.
Third, we compute the shortest-path distance vectors from all landmarks to every node using Dijkstra searches. These pre-baked distance matrices are serialized into flat binary dumps. At query time, the ALT heuristic evaluation reads all sixteen precomputed 32-bit bounds in a single 64-byte L1 cache transaction, guaranteeing zero cache miss penalty in the routing hot loop.
