\section{Офлайн-препроцессинг и сжатие графа}

Для обеспечения микросекундной задержки при маршрутизации вычислительное ядро \texttt{traffic\_core} полностью освобождено от задач парсинга геометрии. Все ресурсоемкие операции вынесены в специализированный офлайн-контур подготовки графа (Graph Builder).

\subsection{Инверсия топологии и реберный граф}

Классический узловой граф (где перекрестки — узлы, дороги — ребра) непригоден для мезоскопической модели, так как при такой архитектуре стоимость маневра (например, запрет поворота) зависит от истории предыдущего шага, что требует внедрения условных переходов в горячем цикле алгоритма. 

В разработанном контуре применена инверсия — \textbf{направленный реберный граф (Edge-based graph)}:
\begin{itemize}
    \item Физические участки дорог (сегменты) становятся \textit{узлами} нового вычислительного графа.
    \item Маневры на перекрестках (переходы между сегментами) становятся \textit{ребрами}.
\end{itemize}
Это позволяет жестко «запечь» все геометрические штрафы (за торможение, прохождение дуги поворота и разгон) в статический вес связующего маневра. Для графа размерности Московской агломерации ($\approx 600$ тыс. дорожных сегментов) генерация связей на перекрестках создает плотную сеть из $\approx 1.5$ млн возможных маневров.

\subsection{Хранение в формате CSR и топологическая пересортировка}

Классическое объектное представление графа в куче (heap) вызывает массовые промахи кэша процессора из-за случайного доступа к памяти. Для преодоления этого барьера (Memory Wall) вся топология сериализуется в формат Compressed Sparse Row (CSR). Граф описывается набором плоских массивов (\textit{Structure of Arrays}):
\begin{enumerate}
    \item \texttt{row\_ptr} (смещения) — массив из $N+1$ элементов (\texttt{uint32\_t}), хранящий индексы начала списка смежных маневров для каждого узла.
    \item \texttt{col\_ind} (цели) — массив из $E$ элементов (\texttt{uint32\_t}), хранящий идентификаторы целевых сегментов.
    \item \texttt{static\_weight} (статика) — массив из $E$ элементов (\texttt{uint16\_t}), хранящий базовое время $T_{free}$.
\end{enumerate}

Для максимизации процента попаданий в кэш L1/L2 на этапе сборки дампа применяется алгоритм топологической пересортировки узлов (Topological Graph Reordering). Рекурсивная бисекция графа переназначает идентификаторы узлов таким образом, чтобы топологически связные сегменты получали смежные адреса в памяти. При загрузке узла контроллером памяти (блоками по 64 байта) аппаратно выполняется предвыборка (Hardware Prefetching) его фактических соседей.

\subsection{Выравнивание кэш-линии (AoS) и предрасчет BPR-задержек}

В то время как статика графа хранится в формате SoA, динамическое состояние (трафик) меняется непрерывно. Если хранить параметры затора разрозненно, вычисление функции BPR потребует нескольких промахов кэша на один узел. Для решения этой проблемы применена архитектура \textit{Array of Structures} (AoS).

Состояние каждого физического сегмента инкапсулируется в структуру \texttt{DynamicNodeState}, которая принудительно выровнена под размер кэш-линии L1 директивой \texttt{alignas(64)}:
\begin{verbatim}
struct alignas(64) DynamicNodeState {
    uint32_t K_magic;                         // Множитель (4 байта)
    std::atomic<uint16_t> mpr_penalty;        // Внешний штраф (2 байта)
    uint16_t _reserved;                       // Padding (2 байта)
    std::atomic<uint16_t> volume_buckets[24]; // Корзинки (48 байт)
    // Оставшиеся 8 байт заполняются нулями (защита от False Sharing)
};
\end{verbatim}

Важнейшим элементом оптимизации является предрассчитанный коэффициент \texttt{K\_magic}. Для исключения делений и возведений в произвольную степень в горячем цикле роутера, базовые константы функции BPR (базовая скорость, емкость сегмента $C_{300}$) аналитически сжимаются в единое целое число на этапе сборки графа:
\begin{equation}
    K_{magic} = \left\lfloor \frac{T_{free} \cdot \left( \frac{V_{free}}{5} - 1 \right)}{C_{300}^2} \cdot 2^{20} \right\rfloor
\end{equation}

Умножение на $2^{20}$ позволяет в реальном времени использовать аппаратную арифметику с фиксированной точкой (битовые сдвиги \texttt{>> 20}) вместо медленных вычислений с плавающей запятой, сокращая время расчета динамического штрафа до 3–4 тактов процессора.

\subsection{Генерация матриц эвристик (ALT Landmarks)}

В процессе препроцессинга также выполняется выборка опорных маяков (Landmarks) для алгоритма ALT. Для равномерного покрытия транспортной сети применяется стратегия \textit{MaxCover} в сочетании с алгоритмом \textit{Border Minmax}. Офлайн-генератор проводит полные обходы графа алгоритмом Дейкстры, фиксируя 32 наиболее равноудаленных маяка, после чего вычисляет и упаковывает расстояния от каждого узла до всех 32 маяков в бинарный дамп графа. Это формирует базу для $O(1)$ вычисления эвристической оценки $H(u, v)$ на лету.
