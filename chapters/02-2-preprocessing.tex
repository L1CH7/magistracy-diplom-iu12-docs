\section{Офлайн-препроцессинг и сжатие графа}

Для обеспечения микросекундной задержки при маршрутизации вычислительное ядро полностью освобождено от задач парсинга геометрии. Все ресурсоемкие операции вынесены в специализированный офлайн-контур подготовки графа.

Классический узловой граф, в котором перекрестки представляются узлами, а дороги ребрами, непригоден для мезоскопической модели. При такой архитектуре стоимость маневра, например запрет поворота, зависит от истории предыдущего шага, что требует внедрения условных переходов в горячем цикле алгоритма. 

В разработанном контуре применена инверсия~-- направленный реберный граф:
\begin{itemize}
    \item Физические участки дорог в виде сегментов становятся узлами нового вычислительного графа.
    \item Маневры на перекрестках, определяющие переходы между сегментами, становятся ребрами.
\end{itemize}
Это позволяет жестко внедрить все геометрические штрафы за торможение, прохождение дуги поворота и разгон в статический вес связующего маневра. Для графа размерности Московской агломерации генерация связей на перекрестках создает плотную сеть из 1.5 млн возможных маневров.

Классическое объектное представление графа в куче вызывает массовые промахи кэша процессора из-за случайного доступа к памяти. Для преодоления аппаратного барьера пропускной способности памяти, известного как стена памяти \cite{mutlu2020primer}, вся топология сериализуется в компактный формат разреженных строк CSR \cite{drepper2007memory}. Граф описывается набором плоских массивов в виде структуры массивов \cite{strzodka_aos_soa}:
\begin{enumerate}
    \item массив смещений указателей строк~-- массив из N+1 элементов, хранящий индексы начала списка смежных маневров для каждого узла.
    \item массив индексов столбцов~-- массив из E элементов, хранящий идентификаторы целевых сегментов.
    \item массив статических весов~-- массив из E элементов, хранящий базовое время проезда свободного ребра.
\end{enumerate}

Для максимизации процента попаданий в кэш процессора первого и второго уровня на этапе сборки дампа применяется алгоритм топологической пересортировки графа. Сортировка вдоль пространственной кривой Мортона (Z-кривой) переназначает идентификаторы узлов так, чтобы геометрически близкие сегменты получали смежные адреса в памяти \cite{drepper2007memory}. При загрузке узла контроллер памяти считывает данные блоками по 64 байта, аппаратно выполняя предвыборку его соседей \cite{butorin2026thread}.

В то время как статика графа хранится в формате структуры массивов, динамическое состояние трафика меняется непрерывно. Если хранить параметры затора разрозненно, вычисление функции задержки потребует нескольких промахов кэша на один узел. Для решения этой проблемы применена архитектура массива структур AoS.

Состояние каждого физического сегмента инкапсулируется в структуру состояния динамического узла, которая принудительно выровнена под размер кэш-линии первого уровня директивой выравнивания по границе 64 байт \cite{drepper2007memory}:
\begin{plaincode}{dynamic_node_state}{Структура динамического состояния узла с выравниванием по кэш-линии}
struct alignas(64) DynamicNodeState {
    uint32_t K_magic;                         // Целочисленный множитель
    std::atomic<uint16_t> mpr_penalty;        // Внешний штраф
    uint16_t _reserved;                       // Заполнитель
    std::atomic<uint16_t> volume_buckets[24]; // Корзинки прогнозов
    // Оставшиеся 8 байт для защиты от ложного разделения данных
};
\end{plaincode}

Важнейшим элементом оптимизации является предрассчитанный целочисленный множитель. Для исключения операций деления и возведения в произвольную степень в горячем цикле роутера, базовые константы функции задержки, включая базовую скорость и емкость сегмента, аналитически сжимаются в единое целое число на этапе сборки графа:
\begin{equation}
    K_{magic} = \left\lfloor \frac{T_{free} \cdot \left( \frac{V_{free}}{5} - 1 \right)}{C_{300}^2} \cdot 2^{20} \right\rfloor
\end{equation}
\where{
    $K_{magic}$ & предрассчитанный 32-битный целочисленный множитель функции задержки; \\
    $T_{free}$ & базовая нижняя граница времени проезда; \\
    $V_{free}$ & скорость свободного потока на сегменте; \\
    $C_{300}$ & емкость ребра для 5-минутного интервала.
}

Умножение на $2^{20}$ позволяет в реальном времени использовать аппаратную арифметику с фиксированной точкой через битовые сдвиги вправо на 20 разрядов вместо медленных вычислений с плавающей запятой, сокращая время расчета динамического штрафа до 3–4 тактов процессора.

При предварительной обработке офлайн-генератор выбирает опорные ориентиры для алгоритма динамического поиска по опорным вершинам. Для равномерного покрытия транспортной сети программа использует стратегию максимального покрытия в сочетании с алгоритмом граничного минмакса \cite{fuchs2010preprocessing}. Генератор обходит граф алгоритмом Дейкстры, фиксирует 32 равноудаленных маяка и упаковывает расстояния от каждого узла до маяков в бинарный дамп графа \cite{goldberg2004alt}. Предварительно рассчитанные расстояния позволяют вычислять эвристическую оценку за константное время.

Офлайн-подготовка картографических данных проходит по строго направленному конвейеру, который выполняет последовательную цепочку шагов от парсинга исходного файла до выгрузки оптимизированного бинарного дампа графа. 

Основные этапы работы конвейера подготовки графа:
\begin{enumerate}
    \item Импорт геоданных: модуль импорта считывает сжатый бинарный файл выгрузки, извлекает вершины, ребра и отношения, после чего записывает их во временную пространственную базу данных.
    \item Пространственная фильтрация: алгоритм удаляет тупиковые ребра, пешеходные пути и изолированные подграфы, а также связывает координаты точек пересечений.
    \item Реберная трансформация графа: конвертер преобразует реляционный граф в направленный реберный. Дорожные сегменты становятся узлами вычислительного графа, а маневры на перекрестках~-- направленными ребрами.
    \item Расчет весов и оптимизация кэша: программа рассчитывает статическое время свободного проезда $T_{free}$ и переупорядочивает узлы вдоль пространственной Z-кривой Мортона для локальности данных в памяти.
    \item Выбор ориентиров: генератор выбирает опорные маяки методом максимального покрытия и рассчитывает матрицу расстояний от узлов графа до маяков.
    \item Формирование структуры графа и сериализация: упаковщик переносит топологию графа в плоские бинарные массивы, выравнивает их по границе 64 байт и записывает в единый бинарный файл для быстрого проецирования в память ядра (mmap).
\end{enumerate}

Конвейер разделяет хранение и обработку данных на три уровня:
\begin{itemize}
    \item Реляционный уровень на базе PostgreSQL: сохраняет сырую геометрию дорожной сети в схеме \texttt{osm} и преобразованный реберный граф в схеме \texttt{eb\_graph}.
    \item Уровень статической сериализации: модуль Graph Builder выгружает оптимизированный граф в набор специализированных бинарных файлов. Файлы \texttt{csr.bin} и \texttt{csr\_rev.bin} содержат топологию сети, \texttt{landmarks.bin}~-- матрицы расстояний до опорных вершин, а \texttt{spatial\_grid.bin}~-- пространственную сетку.
    \item Уровень исполнения: симулятор Traffic Core отображает бинарные дампы в виртуальную память через системный вызов \texttt{mmap}, исключая копирование данных и ускоряя старт системы.
\end{itemize}
