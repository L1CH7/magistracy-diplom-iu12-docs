\section{Related Work}
\label{sec:related}

Shortest path routing literature covers static precomputation and dynamic query-time acceleration. 
Static methods, including Contraction Hierarchies, achieve sub-millisecond query times by adding shortcut edges to the graph. 
These methods require a static network topology. 
Dynamic environments with real-time congestion updates render static shortcut validation obsolete. 

\subsection{Shortest Path Routing Algorithms}
We evaluate three core shortest path routing paradigms that shape the search space exploration:
\begin{itemize}
    \item \textbf{Dijkstra's Algorithm}: Explores nodes in increasing order of distance from the source. The priority key is $key(v) = g(v)$, where $g(v)$ is the exact distance. It guarantees optimal path retrieval but relaxes a large circular search space.
    \item \textbf{A* Search}: Restricts the search space toward destination $t$ using the priority $key(v) = g(v) + w \cdot h(v)$, where $h(v)$ is the Euclidean distance estimate and $w \ge 1.0$ is the heuristic weight. If $w = 1.0$ and $h(v)$ is admissible, the search is optimal. For $w > 1.0$, the search is bounded sub-optimal with path stretch, but significantly narrows the search space.
    \item \textbf{ALT Algorithm}: Integrates A* search with landmark nodes and triangle inequality~\cite{goldberg2004alt}. Given precomputed landmarks $L$, the lower bound estimate from $v$ to $t$ is:
    \begin{equation}
    h_{\text{ALT}}(v) = \max_{l \in L} \{ \max(d(l, t) - d(l, v), d(v, l) - d(t, l)) \}
    \end{equation}
    where $d(\cdot, \cdot)$ is the shortest path distance. The priority key is $key(v) = g(v) + w \cdot h_{\text{ALT}}(v)$. Landmarks provide directed estimates that adapt to congestion changes, making ALT suitable for real-time routing. Landmark selection algorithms~\cite{fuchs2010preprocessing} determine lower bound quality and search space reduction.
\end{itemize} 

Priority queue selection dictates the step latency constant $t_{\text{iter}}$ on sparse road networks~\cite{cherkassky1994shortest}. 
While simple binary heaps outperform pointer-heavy Fibonacci heaps due to better cache locality, they remain bottlenecked by branch mispredictions in element comparison loops~\cite{biggar_sorting}. 
Multi-ary heaps (such as 4-ary and 8-ary heaps) restrict tree depth and improve cache-line-level data layout, accelerating shortest path routing on road graphs~\cite{outerloop_heap}. 
For integer edge weights, radix heaps group keys into dynamic buckets to achieve near-constant time complexities~\cite{ahuja1990faster}. 
Similarly, relaxed sorting in bucket queues (such as Delta-stepping~\cite{meyer2003delta}) avoids strict ordering overhead. 

Breitling et al.~\cite{quickheap_arxiv} propose QuickHeap to minimize comparison counts through lazy sorting with SIMD vectorization. 
However, their sifting routine introduces branch prediction overhead, and cache misses during graph traversal on standard road networks mask their SIMD speedups. 
We address these limitations using a cache-conscious SIMD $d$-ary heap layout.

\subsection{Architectural Divergence from the KIT SimdQuickHeap Framework}
The KIT framework evaluated their vectorized \texttt{SimdQuickHeap} layout on server-class AVX-512 AMD EPYC CPUs using static, node-based DIMACS networks, reporting that graph-reading cache misses masked queue speedups~\cite{quickheap_arxiv}. They bypassed the lack of a native \texttt{decreaseKey} by packing vertex ID and distance into a 64-bit word. 

We shift this paradigm by targeting real-time Smart City loops with dynamic weights on a dense Edge-Based Graph, using a 256-bit AVX2 pipeline on consumer-class hardware (AMD Ryzen 5 5600H). To resolve the memory bottlenecks that masked SIMD speedups in the KIT benchmarks, we combine CSR layout, Morton spatial curve (Z-order) reordering, and \texttt{alignas(64)} AoS padding. This spatial compaction prevents memory stalls, ensuring queue efficiency dominates the execution flow (as shown by our OLS coefficient of $3.3214$ for $T_{\text{queue}}$).
