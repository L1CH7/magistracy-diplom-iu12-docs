\section{Алгоритмическая реализация динамического поиска путей и векторные оптимизации}

Сердцем вычислительного ядра является класс маршрутизатора, реализующий алгоритм поиска кратчайшего пути с временной зависимостью. Для обеспечения заявленной пропускной способности в тысячи запросов в секунду код маршрутизатора глубоко оптимизирован с использованием векторных инструкций процессора.

Векторизация многоарной кучи с применением процессорных инструкций.
В классической реализации алгоритма Дейкстры или направленного поиска основным узким местом (занимающим до 60\% процессорного времени) является извлечение узла с минимальным весом из очереди с приоритетом. Традиционно для этого используется стандартная очередь приоритетов на базе двоичной кучи, имеющая логарифмическую глубину.

В разработанном ядре осуществлен переход к многоарным кучам (4-арной и 8-арной в формате SoA), которые уменьшают глубину дерева в два и три раза соответственно, что критически важно для снижения количества промахов кэша процессора при обходе уровней \cite{outerloop_heap}. Однако увеличение арности кучи требует нахождения минимума среди всех потомков узла (до 8 на каждом уровне), что резко увеличивает количество инструкций сравнения и условных переходов.

Для нивелирования этих затрат в проекте реализован поиск минимального потомка в 8-арной куче с использованием 256-битных векторных инструкций AVX2 \cite{kusswurm2014modern, fog_optimizing_cpp}. Восемь 32-битных весов потомков загружаются в один векторный регистр, после чего невалидные индексы маскируются, а поиск минимального значения осуществляется за счет каскада векторных минимумов и перестановок, исключающих ветвление процессора:
\begin{plaincode}{find_min_child_avx2}{Поиск минимального потомка в 8-арной SoA-куче с помощью векторных инструкций}
// Загрузка весов 8 потомков (32-битных) в векторный регистр
__m256i v = _mm256_loadu_si256(reinterpret_cast<const __m256i*>(&weights_[first]));

// Маскирование невалидных потомков (индекс >= size_) значением бесконечности (0xFFFFFFFF)
__m256i v_first = _mm256_set1_epi32(first);
__m256i v_indices = _mm256_add_epi32(v_first, v_offsets);
__m256i mask = _mm256_cmpgt_epi32(v_size, v_indices);
v = _mm256_blendv_epi8(inf, v, mask);

// Поиск горизонтального минимума с помощью инструкций _mm256_min_epu32 и перестановок
__m256i p1 = _mm256_permute2x128_si256(v, v, 1);
__m256i m1 = _mm256_min_epu32(v, p1);
__m256i m2 = _mm256_min_epu32(m1, _mm256_shuffle_epi32(m1, _MM_SHUFFLE(1, 0, 3, 2)));
__m256i m3 = _mm256_min_epu32(m2, _mm256_shuffle_epi32(m2, _MM_SHUFFLE(2, 3, 0, 1)));
uint32_t min_w = _mm256_extract_epi32(m3, 0);

// Получение индекса минимального потомка через маску совпадения
uint32_t match_mask = _mm256_movemask_ps(_mm256_castsi256_ps(
    _mm256_cmpeq_epi32(v, _mm256_set1_epi32(min_w))));
uint32_t min_idx = first + __builtin_ctz(match_mask);
\end{plaincode}
Векторизация устраняет все условные переходы при поиске дочернего узла. Процессор выбирает минимального потомка за несколько аппаратных тактов без риска сброса конвейера из-за ошибочного предсказания переходов \cite{biggar_sorting}. Дополнительно применяется инструкция упреждающей выборки памяти \texttt{\_mm\_prefetch} для следующей строки кэша L1, что обеспечивает максимальную аппаратную скорость выполнения.

Механизм безблокировочного резервирования и интерполяции.
В процессе раскрытия вершин алгоритм динамического направленного поиска оценивает вес каждого маневра. Для чтения объемов трафика из временных интервалов резервирования маршрутизатор не использует транзакционные мьютексы. Массивы атомарных переменных считываются со слабым порядком памяти \cite{cpp_p2055r1, cpp_p0668r5}. 

Для устранения ступенчатости штрафов реализован механизм линейной интерполяции времени, который считывает объемы из двух соседних 5-минутных слотов и интерполирует непосредственно квадраты плотности потока, применяя заранее вычисленный целочисленный коэффициент:
\begin{plaincode}{bpr_lerp_fixed_point}{Расчет задержки методом линейной интерполяции}
uint32_t p1 = K_magic * v1 * v1;
uint32_t p2 = K_magic * v2 * v2;
uint32_t bpr_penalty = (p1 + (p2 - p1) * 
    (eta % 300) / 300) >> 20;
\end{plaincode}
После того как оптимальный путь найден, роутер осуществляет резервирование емкости. Проходя по восстановленному пути, для каждого сегмента вызывается операция атомарного сложения, которая инкрементирует значение в соответствующем временном интервале. Это математически аппроксимирует эффект перераспределения потока, уводя следующих агентов на альтернавые маршруты.

Пространственные индексы модуля принятия решений.
Для обеспечения мгновенной реакции модуля принятия решений на инциденты реализован сверхбыстрый пространственный индекс. Сложные структуры данных на базе классических пространственных деревьев, основанные на указателях в куче, были заменены на регулярную пространственную сетку, развернутую в непрерывном массиве \cite{drepper2007memory}. 

Привязка географической геометрии дорог к ячейкам сетки выполняется на этапе предварительной обработки. В реальном времени модуль принятия решений формирует ограничивающую рамку зоны инцидента и за константное время получает доступ к списку идентификаторов ребер, попавших в ячейки. Затем модуль принятия решений выставляет директивные штрафы в атомарное поле штрафов целевых сегментов. Благодаря строгой архитектуре кэширования, поиск затронутых ребер и обновление штрафов происходят за доли микросекунды, не блокируя работу соседних потоков пула маршрутизатора.

Сквозной процесс обработки запросов маршрутизации.
Для минимизации накладных расходов при передаче данных между компонентами системы (клиентский графический интерфейс пользователя на языке Python, сетевой шлюз и высокопроизводительное вычислительное ядро) разработан специализированный асинхронный протокол взаимодействия на базе бинарной сериализации и шины сообщений сетевого транспорта. 

Сквозной жизненный цикл выполнения запроса на расчет маршрута состоит из следующих последовательных этапов:
\begin{enumerate}
    \item Инициализация запроса: Клиентское приложение перехватывает событие клика на веб-карте и через встроенный механизм канала веб-коммуникации передает асинхронный запрос с массивом промежуточных географических точек на сетевой шлюз.
    \item Бинарная сериализация: Сетевой шлюз с помощью встроенного модуля упаковки структур упаковывает параметры запроса в плоский бинарный буфер фиксированного формата. Это исключает медленный парсинг строк формата JSON на стороне вычислительного демона.
    \item Сетевой транспорт: Сериализованный буфер отправляется по сокету сетевого транспорта с использованием синхронного паттерна запрос-ответ в фоновый диспетчерский поток вычислительного ядра.
    \item Пространственная привязка: Вычислительный поток ядра принимает сообщение и выполняет привязку координат старта и финиша к ближайшим ребрам графа дорожной сети, опрашивая плоский пространственный индекс за константное время.
    \item Поиск пути во времени: Идентификаторы ребер передаются в маршрутизатор. Алгоритм осуществляет поиск кратчайшего пути на графе компактного формата. На каждом шаге релаксации ребер вычисляется динамический вес сегментов с учетом ожидаемого времени прибытия. Стоимость проезда определяется через менеджер объемов по формуле функции задержки с линейной интерполяцией плотности по 5-минутным временным корзинкам.
    \item Формирование многочастного ответа: Результаты поиска упаковываются в высокоэффективное многочастное сообщение для исключения копирования памяти при сборке пакета.
    \item Отрисовка маршрута: Сетевой шлюз распаковывает бинарные фреймы, преобразует плоскую геометрию в векторный формат и возвращает ответ клиенту, который отрисовывает оптимальный маршрут на карте.
\end{enumerate}
