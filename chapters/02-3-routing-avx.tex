\section{Алгоритмическая реализация динамического поиска путей и векторные оптимизации}

Сердцем вычислительного ядра является класс маршрутизатора, реализующий алгоритм поиска кратчайшего пути с временной зависимостью. Для обеспечения заявленной пропускной способности в тысячи запросов в секунду код маршрутизатора глубоко оптимизирован с использованием векторных инструкций процессора.

При поиске кратчайшего пути основным узким местом выступает извлечение узла с минимальным весом из очереди приоритетов. Традиционная двоичная куча создает логарифмическую глубину дерева, что замедляет работу.

Разработанное ядро использует многоарные кучи, в частности 4-арную и 8-арную в формате SoA. Они уменьшают глубину дерева в два и три раза соответственно, что снижает количество промахов кэша процессора при обходе уровней \cite{outerloop_heap}. Однако высокая арность кучи требует поиска минимума среди всех потомков узла, число которых на каждом уровне достигает восьми. Это увеличивает количество сравнений и условных переходов.

Для нивелирования этих затрат в проекте реализован поиск минимального потомка в 8-арной куче с использованием 256-битных векторных инструкций AVX2 \cite{kusswurm2014modern, fog_optimizing_cpp}. Восемь 32-битных весов потомков загружаются в один векторный регистр, после чего невалидные индексы маскируются, а поиск минимального значения осуществляется за счет каскада векторных минимумов и перестановок, исключающих ветвление процессора:
\begin{plaincode}{find_min_child_avx2}{Поиск минимального потомка в 8-арной SoA-куче с помощью векторных инструкций}
// Загрузка весов 8 потомков в формате 32-битных чисел в векторный регистр
__m256i v = _mm256_loadu_si256(reinterpret_cast<const __m256i*>(&weights_[first]));

// Маскирование невалидных потомков значением бесконечности 0xFFFFFFFF при выходе индекса за пределы size_
__m256i v_first = _mm256_set1_epi32(first);
__m256i v_indices = _mm256_add_epi32(v_first, v_offsets);
__m256i mask = _mm256_cmpgt_epi32(v_size, v_indices);
v = _mm256_blendv_epi8(inf, v, mask);

// Поиск горизонтального минимума с помощью инструкций _mm256_min_epu32 и перестановок
__m256i p1 = _mm256_permute2x128_si256(v, v, 1);
__m256i m1 = _mm256_min_epu32(v, p1);
__m256i m2 = _mm256_min_epu32(m1, _mm256_shuffle_epi32(m1, _MM_SHUFFLE(1, 0, 3, 2)));
__m256i m3 = _mm256_min_epu32(m2, _mm256_shuffle_epi32(m2, _MM_SHUFFLE(2, 3, 0, 1)));
uint32_t min_w = _mm256_extract_epi32(m3, 0);

// Получение индекса минимального потомка через маску совпадения
uint32_t match_mask = _mm256_movemask_ps(_mm256_castsi256_ps(
    _mm256_cmpeq_epi32(v, _mm256_set1_epi32(min_w))));
uint32_t min_idx = first + __builtin_ctz(match_mask);
\end{plaincode}
Векторизация устраняет все условные переходы при поиске дочернего узла. Процессор выбирает минимального потомка за несколько аппаратных тактов без риска сброса конвейера из-за ошибочного предсказания переходов \cite{biggar_sorting}. Дополнительно применяется инструкция упреждающей выборки памяти \texttt{\_mm\_prefetch} для следующей строки кэша L1, что обеспечивает максимальную аппаратную скорость выполнения.

При раскрытии вершин алгоритм динамического поиска оценивает вес каждого маневра. Маршрутизатор считывает объемы трафика из временных интервалов без использования транзакционных мьютексов. Код обращается к массивам атомарных переменных со слабым порядком памяти \cite{cpp_p2055r1, cpp_p0668r5}. 

Для устранения ступенчатости штрафов реализован механизм линейной интерполяции времени, который считывает объемы из двух соседних 5-минутных слотов и интерполирует непосредственно квадраты плотности потока, применяя заранее вычисленный целочисленный коэффициент:
\begin{plaincode}{bpr_lerp_fixed_point}{Расчет задержки методом линейной интерполяции}
uint32_t p1 = K_magic * v1 * v1;
uint32_t p2 = K_magic * v2 * v2;
uint32_t bpr_penalty = (p1 + (p2 - p1) * 
    (eta % 300) / 300) >> 20;
\end{plaincode}
После того как оптимальный путь найден, роутер осуществляет резервирование емкости. Проходя по восстановленному пути, для каждого сегмента вызывается операция атомарного сложения, которая инкрементирует значение в соответствующем временном интервале. Это математически аппроксимирует эффект перераспределения потока, уводя следующих агентов на альтернавые маршруты.

Для мгновенной реакции модуля принятия решений на дорожные инциденты разработан быстрый пространственный индекс. Классические пространственные деревья с указателями в куче заменены регулярной сеткой в непрерывном массиве памяти \cite{drepper2007memory}. 

Привязка географической геометрии дорог к ячейкам сетки выполняется на этапе предварительной обработки. В реальном времени модуль принятия решений формирует ограничивающую рамку зоны инцидента и за константное время получает доступ к списку идентификаторов ребер, попавших в ячейки. Затем модуль принятия решений выставляет директивные штрафы в атомарное поле штрафов целевых сегментов. Благодаря строгой архитектуре кэширования, поиск затронутых ребер и обновление штрафов происходят за доли микросекунды, не блокируя работу соседних потоков пула маршрутизатора.

Специализированный асинхронный протокол на базе бинарной сериализации минимизирует накладные расходы при обмене данными между клиентом на Python, сетевым шлюзом и вычислительным ядром C++. 

Жизненный цикл выполнения запроса на расчет маршрута состоит из следующих шагов:
\begin{enumerate}
    \item Инициализация запроса: клиентское приложение перехватывает клик на карте и передает запрос с массивом географических точек на шлюз через WebSocket.
    \item Сериализация: шлюз упаковывает параметры запроса в плоский бинарный буфер фиксированного формата, что исключает медленный парсинг JSON на стороне вычислительного ядра.
    \item Сетевой транспорт: шлюз отправляет бинарный буфер в фоновый поток вычислительного ядра через сетевой сокет.
    \item Пространственная привязка: вычислительный поток принимает сообщение и привязывает координаты старта и финиша к ближайшим ребрам графа через плоский пространственный индекс за константное время.
    \item Поиск пути: маршрутизатор ищет кратчайший путь на компактном графе. При релаксации ребер алгоритм рассчитывает динамический вес сегментов с учетом ожидаемого времени прибытия, а менеджер объемов интерполирует плотность по 5-минутным корзинам.
    \item Формирование ответа: ядро упаковывает результаты в многочастное сообщение (multipart message) для исключения лишнего копирования памяти.
    \item Отрисовка: шлюз распаковывает бинарные фреймы, преобразует геометрию в векторный формат и возвращает ее клиенту для визуализации на карте.
\end{enumerate}
